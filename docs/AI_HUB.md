# AI Hub

The Hub is a registry for two reviewed local adapter IDs, package validation, runtime load/reload, per-source/job sessions, and bounded inference calls. It does not discover modules by importing package code. Package files are configuration plus an approved Ultralytics detection checkpoint. Segmentation, pose, arbitrary state dictionaries, and unknown tasks fail validation rather than being guessed.

API and ingestion worker retain their existing separate processes and lease. The authenticated catalog is `GET /api/ai/modules`; admin endpoints validate and queue reload; source assignment is `GET/PUT /api/cameras/{id}/modules`. Reload writes an atomic worker control file in the existing shared handoff directory. The worker loads at its control-loop boundary, so existing loaded model is not torn down mid-inference. A failed load is reported explicitly and does not trigger simulation. Package selection is stored in existing rule configuration; no parallel ingestion worker or model database migration was added.

Ultralytics model weights are shared read-only under a package lock; ByteTrack state is separate per `(session_id, source_id)`. Inference is serialized for a shared model runtime. The current live worker already uses one latest-frame slot per source and isolates module errors per source frame. FILE jobs are queued in the existing shared handoff volume; one job runs at a time independently of the LIVE loop. Progress is written every ten frames; cancellation is checked between frames; interrupted jobs become `FAILED` on worker restart. Result files cap stored events at 10,000, job history caps at 100, and terminal jobs can be explicitly deleted. A partial/module-failed job is never reported complete.

`HUB_INFRA_READY` means catalog, validators, runtime adapter, contracts, and integration paths exist. It does not mean a trained package is present. `REAL_MODEL_VALIDATED` requires successful validation with that trusted checkpoint and actual inference. `CAMERA_VALIDATED` requires separately authorized physical stream testing. The current repo contains no checkpoint, so neither latter state is claimed.

The package runner uses `predict` with BGR-to-RGB conversion and original-pixel `xyxy` outputs. ByteTrack uses the locked Ultralytics API with session-local tracker instances. FILE mode derives event timing from media timestamps; LIVE duration uses monotonic time. No source URL or credential enters model context. The Hub does not upload footage or download weights. FILE job routes are `POST/GET /api/ai/jobs`, `GET /api/ai/jobs/{id}`, `POST /api/ai/jobs/{id}/cancel`, `DELETE /api/ai/jobs/{id}`, `GET /api/ai/jobs/{id}/results`, and authenticated `GET /api/ai/jobs/{id}/media`. Browser playback still depends on codec support.
