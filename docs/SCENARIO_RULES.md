# Scenario rule semantics

`ScenarioEvaluator` owns state per job/source session. Anchors use normalized image coordinates when passed to its geometric helpers. People/vehicle package defaults use bottom-center for zone geometry. Polygon membership uses ray casting. Zone entry means an observed outside-to-inside transition; first appearance already inside is ignored. Directional crossing requires a sign change across the configured line and an explicit `A_TO_B` or `B_TO_A` direction. Dwell requires a track to remain inside for the configured duration. Current helper state supports a short disappearance grace, event cooldown, and reset; no cross-camera identity is performed.

The package defaults include one-second entry observation, 30-second person dwell, and line crossing hysteresis guidance. Fire/smoke package scenarios require two seconds of continuous observation, tolerate 1.5 seconds of disappearance and use a 60-second cooldown. The combined smoke/fire scenario requires both labels in the same processed frame; it does not mean smoke is a prerequisite for the separate fire scenario. Existing persistence deduplicates one active incident per camera/rule, not per zone. A fire/smoke box is an operator review signal, not certified alarm confirmation. Geometry and scenario policy are package configuration; there is no claim that monitoring schedules execute.

The existing application `Rule` controls event minimum duration/cooldown and zone geometry. LIVE durations use monotonic elapsed time and reset after a source gap; FILE analysis uses media time. Repeated detections update a deduplicated active incident; operator resolution and scene clearance remain separate. Synthetic scenarios are a distinct explicit plugin and always carry the `SIMULATED` marker.
